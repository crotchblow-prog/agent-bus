## 1. `scripts/analyzers/regime_sensitivity.py` (new)

Pure compute over 5 years of weekly historical data. Universe = 51 tickers (brief had 52; `FB` is a typo for old Meta — Carina confirmed drop FB, keep META):

```
AAPL ABBV ABT ADBE ADP AMD AMGN AMT AMZN AVGO BA BAC BIIB BMY C CHTR
CMCSA CME COST CSCO CSX CVS EA EBAY EQIX F FTNT GILD GOOGL HD IBM
INTC INTU ISRG JNJ JPM KO LIN MRK MS MSFT NFLX NKE NVDA SBUX T TMO
TMUS TSLA TSM UNH UPS V VRTX VZ WFC WMT XOM META
```

Hard-code as `UNIVERSE: tuple[str, ...]` at module top; explicit list, no env var. TSM stays IN despite Taiwan ADR — its trading behavior mirrors US large-cap semis, not Chinese ADRs.

Compute these 4 metrics per ticker:

- **`beta_normal`**: OLS β of weekly returns vs SPX, restricted to weeks where VIX ∈ [12, 20].
- **`beta_stress`**: OLS β of weekly returns vs SPX, restricted to weeks where VIX > 20.
- **`vix_spike_decay_pct`**: For events where VIX rises ≥ 20% in a single trading day, compute the median 5-trading-day cumulative return of the ticker following the spike.
- **`vix_crush_recovery_pct`**: For events where VIX falls ≥ 30% from its 60-day high, compute the median 5-trading-day cumulative return following the crush.

**Sample size guard (Carina-locked):** any metric whose underlying event count is < 8 → `confidence = "low"` and the ticker is **excluded from sensitivity_tags assignment**. Threshold is `MIN_SAMPLE_SIZE = 8`. Don't make it configurable yet.

Sensitivity tag assignment (a ticker may have multiple):

```
high_normal:   beta_normal > 1.3 AND beta_stress < beta_normal
high_stress:   beta_stress > 1.5 AND beta_stress > beta_normal
crisis_alpha:  vix_spike_decay_pct < -10
mean_reverter: vix_crush_recovery_pct > 5 AND vix_spike_decay_pct < -5
defensive:     |beta_normal| < 0.8 AND |beta_stress| < 1.0
```

Output: `config/regime_sensitivity.json` (committed):

```json

  "min_sample_size": 8,

```

CLI entry point: `python scripts/analyzers/regime_sensitivity.py` runs the full compute and writes the JSON. Make it idempotent — rerun should produce a near-identical file (only `computed_at` changes if data hasn't moved).

Use yfinance for historical data — same dependency the rest of the pipeline already uses, no new fetcher class needed unless you want one. Network failures: log + retry once, then write a partial file with whatever tickers succeeded. Per-ticker failures don't block the rest.
