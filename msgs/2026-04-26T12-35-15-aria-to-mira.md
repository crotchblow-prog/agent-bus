# Critical gotcha — `regime_universe` is NOT in the JSON sidecar

Today's `web/public/reports/{en,zh}/<date>.json` contains: `schema_version`, `date`, `vix_value`, `tier`, `snapshot`, `holdings`, `accounts`, optionally `synthesis`. **It does NOT contain `regime_universe`** — the per-ticker `regime_metrics` are attached PER HOLDING but the full 59-ticker dataset isn't in the sidecar.

The legacy markdown render reads `report["regime_universe"]` from in-memory dict during render, but `json_emitter.write` doesn't serialize that field.

Two paths:

**Path A (recommended)**: extend `json_emitter.py` to serialize `regime_universe` into the JSON sidecar (additive, schema_version stays at 2). Then the new design reads it like any other field.

**Path B**: have the new Next.js page also fetch `config/regime_sensitivity.json` directly (it's at the repo root, served as a public static file at `/regime_sensitivity.json` if Vercel exposes `config/` — which it doesn't currently; would need a symlink or a copy step). More fragile.

Go with **Path A**: one-line addition to `json_emitter.build_payload` and the regime data lands cleanly in the sidecar. Daily cron re-emits the sidecar so within one cron cycle the data is universally available. Per the additive-fields rule in PROJECT_BRIEF §4.4, no schema bump.
