# hashfinder.vercel.app — bug report from Playwright pass

I tested the live deploy at https://hashfinder.vercel.app with Playwright
(headless Chromium, mocked geolocation). Three real bugs to fix; one papercut.
Source paths reference the `hash-finder/` project on iCloud.

## P0 — Production is running on a Clerk DEVELOPMENT instance

Every page logs:

> Clerk: Clerk has been loaded with development keys. Development instances
> have strict usage limits and should not be used when deploying your
> application to production.

Confirmed because `/host` redirects to `https://allowing-treefrog-54.accounts.dev/sign-in?...`
— that subdomain is Clerk's dev-instance pattern. Sign-in/up will hit dev
rate limits and is not the real Clerk environment for production.

**Fix:**
1. In Clerk dashboard, create (or promote) a Production instance for
   `hashfinder.vercel.app`.
2. In Vercel project env (Production scope only), replace
   `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` with the
   production keys (`pk_live_…` / `sk_live_…`). Leave Preview/Development on
   the dev keys if you want.
3. Redeploy production.

## P1 — `/api/events/nearby` validation is inconsistent

Tested:

| Request                                            | Got                              | Expected |
|----------------------------------------------------|----------------------------------|----------|
| `/api/events/nearby` (no params)                   | 200 `{"events":[]}`              | 400 |
| `/api/events/nearby?lat=37.77`                     | 200 `{"events":[]}`              | 400 |
| `/api/events/nearby?lat=foo&lng=bar`               | 400 `{"error":"…required"}`      | 400 ✓ |
| `/api/events/nearby?lat=999&lng=999`               | 200 `{"events":[]}`              | 400 (out of range) |

Validator only triggers when both params parse as NaN. Missing params and
out-of-range values silently return empty results, which masks client bugs.

**Fix in** `app/api/events/nearby/route.ts` — require both `lat` and `lng`,
parse with `Number()`, reject if `Number.isNaN()`, and clamp/reject
`lat ∉ [-90, 90]` or `lng ∉ [-180, 180]`. A small Zod schema would do it
since you already depend on zod.

## P1 — Console flooded with CORS errors on every navigation

Every page (`/`, `/find`, `/events/[id]`) logs:

> Access to fetch at `https://allowing-treefrog-54.accounts.dev/sign-in?...`
> (redirected from `https://hashfinder.vercel.app/host?_rsc=…`) … blocked by
> CORS policy

Cause: Next.js auto-prefetches `<Link href="/host">` in the nav. The prefetch
is an RSC fetch (`?_rsc=…`); `proxy.ts` (Clerk's `auth.protect()`) redirects
it to `accounts.dev`, which fails the browser's CORS preflight. Functionally
harmless but spams the console and wastes a request per page-load.

**Fix:** simplest is to disable prefetch on the Host nav link
(`<Link href="/host" prefetch={false}>`). Cleaner is to have `proxy.ts`
detect RSC requests (`request.headers.get('rsc') === '1'` or the `_rsc`
search param) and return `new NextResponse(null, { status: 401 })` instead
of `auth.protect()`-ing them.

## P2 — `/events/[id]` page uses the generic homepage `<title>`

Visited `/events/4` (London H3, "Saturday Hash"). Page body renders fine,
but `<title>` is `"On-On — find a hash near you"` — same as the homepage.
Hurts share previews and tab UX.

**Fix:** add `generateMetadata({ params })` in `app/events/[id]/page.tsx`
that fetches the event and returns `{ title: \`${event.title} — ${event.kennel}\` }`.
