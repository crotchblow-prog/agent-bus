Carina, MIRA hit a real macOS limitation installing the launchd cron. **The daemon installs but won't fire** — needs your decision before tomorrow's 22:00 Taipei tick (silenced for now).

## What broke

`launchctl kickstart` exits 126 with:
```
shell-init: getcwd: Operation not permitted
/bin/bash: <path>/scripts/run_daily.sh: Operation not permitted
```

Root cause: macOS TCC sandboxes launchd-spawned `/bin/bash` separately from interactive shells. The Full Disk Access you granted to your Terminal/Claude Code session earlier today does NOT propagate to the launchd subject. Anything inside iCloud Drive (`~/Library/Mobile Documents/com~apple~CloudDocs/`) is TCC-protected. Result: launchd can't read `run_daily.sh`.

## Two options — your call

### Option A: Grant `/bin/bash` Full Disk Access directly

System Settings → Privacy & Security → Full Disk Access → "+" → Cmd-Shift-G → type `/bin/bash` → Add. (`/bin` is hidden in Finder, hence the chord.)

**Pros**:
- 30 seconds, reversible in 5 seconds.
- Keeps the iCloud-shared repo (which means you and I keep cross-machine `.env.local` and working-tree visibility).
- No git remote churn.

**Cons**:
- Slight security cost: bash gets blanket disk access. (You said MIRA is a sandbox, so low concern operationally.)
- macOS minor updates have been known to re-broker TCC for system binaries. If that happens you'd re-grant. Operational fragility ~2x/year.
- Doesn't address MIRA's other real concern: iCloud Drive can evict files to the cloud and a `read` may return `EAGAIN`. Probably theoretical for files actively in use, but it's a known launchd anti-pattern.

### Option B: Relocate repo out of iCloud (e.g. `~/Projects/StockPulse`)

MIRA scripts a fresh clone, regenerates the venv, regenerates the plist with the new path, re-bootstraps. ~10 min. ARIA does the same on her side.

**Pros**:
- Permanent fix to the TCC class of issue.
- Eliminates the iCloud-driven working-tree drift MIRA and I both feel (her local tree was dirty after my afternoon renames synced through iCloud).
- iCloud-eviction reliability concern goes away.

**Cons**:
- One-time cost: each machine independently `git pull`s instead of getting iCloud sync. Slightly more friction for "I wrote it, can MIRA see it?" — we'd push to GitHub instead.
- `.env.local` becomes per-machine (not synced via iCloud). You'd need to put the keys on each machine independently. Marginal: it's already on both machines today via iCloud.
- Touches the path I have wired into Claude Code's `cwd` for our sessions. We'd reconfigure that.
