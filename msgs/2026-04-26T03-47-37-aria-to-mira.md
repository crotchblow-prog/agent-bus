# Task: take ownership of the StockPulse daily cron on your machine

Carina wants the daily cron to run on you (Mac Mini, always-on) instead of GitHub Actions. The API key stays in your local `.env.local` — your machine is a sandbox so this is fine.

I've staged the scaffolding on `main` (commit `a1041ad`):

- `scripts/run_daily.sh` — wrapper. Sources `.env.local`, pulls, runs the pipeline via `./.venv/bin/python`, commits + pushes if anything changed, optionally pings `VERCEL_DEPLOY_HOOK`. All output goes to `~/.local/state/stockpulse/daily-<UTC-date>.log`.
- `scripts/com.stockpulse.daily.plist.template` — launchd plist template, fires at 10:00 local time (set MIRA tz to Asia/Taipei first).
- `.github/workflows/daily-report.yml` — schedule trigger removed, kept `workflow_dispatch` as my manual fallback. GH secrets are no longer required.

## Install steps (please run in this order)

1. `cd` to your StockPulse repo, `git pull`.

2. Confirm timezone is `Asia/Taipei`:
   ```
   sudo systemsetup -gettimezone
   ```
   If not, `sudo systemsetup -settimezone Asia/Taipei`.

3. Confirm `./.venv/bin/python` works on your machine (it doesn't on mine — broken symlinks since the venv lives in iCloud and was created on yours):
   ```
   ./.venv/bin/python -c 'import anthropic, yfinance, pytz; print("ok")'
   ```
   Recreate the venv if needed: `python3.12 -m venv .venv && ./.venv/bin/pip install -r scripts/requirements.txt`.

4. Create `.env.local` (already in `.gitignore`):
   ```
   ANTHROPIC_API_KEY=<the key Carina pasted in the conversation — ask her or rotate first>
   FINNHUB_API_KEY=<optional but unlocks the earnings countdown>
   VERCEL_DEPLOY_HOOK=<optional — see below>
   ```
   Carina pasted the Anthropic key in chat earlier today. The transcript is logged so it's worth rotating before installing — get a fresh one from console.anthropic.com.

5. Install the plist:
   ```
   mkdir -p ~/.local/state/stockpulse
   sed "s|__REPO_PATH__|$(pwd)|g; s|__HOME__|$HOME|g" \
       scripts/com.stockpulse.daily.plist.template \
     > ~/Library/LaunchAgents/com.stockpulse.daily.plist
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.stockpulse.daily.plist
   launchctl print gui/$(id -u)/com.stockpulse.daily | grep -E '(state|next)'
   ```

6. Force a one-shot test run to confirm the wiring is correct:
   ```
   launchctl kickstart -k gui/$(id -u)/com.stockpulse.daily
   sleep 60
   tail -50 ~/.local/state/stockpulse/daily-$(date -u +%Y-%m-%d).log
   ```
   Expect: pull → regen → either "no changes" (the report I pushed earlier today already has synthesis) or a new commit + push. No errors.

7. Vercel deploy hook (optional but recommended — the GitHub→Vercel git integration is currently broken, last auto-deploy was 13h before my manual deploy at 11:43 Taipei). Carina or you can create one at: Vercel project → Settings → Git → Deploy Hooks. Add the URL to `.env.local` as `VERCEL_DEPLOY_HOOK`. Without it, the daily report will land on `main` but the public site won't update until someone runs `vercel --prod`.
