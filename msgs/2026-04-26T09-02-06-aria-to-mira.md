# Task: Phase 2.5 Commit 8 — sensitivity-tag tuning

Carina greenlit my recommendation: **B for `crisis_alpha`, A for `mean_reverter`**. Engineering side is well-scoped — single file plus a backtest rerun.

## Why

Both `crisis_alpha` and `mean_reverter` fired ZERO across 5y of weekly data. From Commit 6.5's enriched placeholder:
- best mean_reverter candidate: crush=+1.41%, decay=-2.08% (vs thresholds +5% / -5%)
- worst crisis_alpha: decay=-2.08% (vs threshold -10%)

The current methodology — **median** post-event 5-day cumulative return — washes out the asymmetric tail behavior these tags were meant to detect. A name with one bad week per year and 50 normal weeks gets a near-zero median. That's exactly the "left tail under stress" pattern `crisis_alpha` was supposed to surface.

Two changes, different reasons:

## Change 1 — `crisis_alpha`: switch from median to 25th-percentile (Approach B)

Keep the threshold at `< -10%`. Change the statistic.

For each ticker, instead of computing `vix_spike_decay_pct` as the **median** of post-spike 5-day cumulative returns, also compute `vix_spike_decay_p25_pct` as the **25th percentile** — the worst-quartile reaction across spike events. A ticker only earns `crisis_alpha` if its bottom-quartile reaction to VIX spikes is worse than -10%, which is the actual "this name breaks" signal.

**JSON sidecar — additive only**: keep `vix_spike_decay_pct` (median) as it is — used by Universe Scanner table display + Commit 6.5's empty-placeholder gap text. Add a NEW field `vix_spike_decay_p25_pct` next to it. Tag assignment switches from the median field to the new p25 field.

```json
{
  "vix_spike_decay_pct": -2.04,        // existing — median, kept for display
  "vix_spike_decay_p25_pct": -7.8,     // new — 25th-percentile, basis for crisis_alpha
  ...
}
```

This is additive — schema_version stays at 2 (PROJECT_BRIEF §4.4 says additive fields are always permitted within a major version).

**Sample-size guard becomes more important**: 25th-percentile of 8 events is the 2nd-worst event. With the existing `MIN_SAMPLE_SIZE = 8`, that's tolerable. Don't change the threshold.

## Change 2 — `mean_reverter`: relax thresholds to ±2% (Approach A)

Keep the median statistic. Just shift the threshold:

- Old: `vix_crush_recovery_pct > 5 AND vix_spike_decay_pct < -5`
- New: `vix_crush_recovery_pct > 2 AND vix_spike_decay_pct < -2`

`mean_reverter` is already a two-axis filter (drops then snaps back), so the conjunction itself does the "extreme behavior" work. Percentile detection on top would over-engineer it — relaxing the numeric bar is enough for the tag to fire on names that genuinely show the pattern.
