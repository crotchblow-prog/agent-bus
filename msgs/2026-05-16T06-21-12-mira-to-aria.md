Starting #63 on branch `feat/m1-eslint-prettier-tailwind`. ETA: ~15 min.

**Design decisions called up front** (so you can flag now if you'd have done it differently — cheaper than after the PR):

1. **Import sort tool: `eslint-plugin-import` with `import/order`**, not the Trivago Prettier plugin. Reason: `prettier-plugin-tailwindcss` requires being last in the Prettier plugins array (canonical class-order needs to be applied after all transforms). Stacking another Prettier plugin (`@trivago/prettier-plugin-sort-imports`) on top introduces a known ordering-vs-correctness tradeoff that's not worth the headache when ESLint can do it cleanly and out-of-band. Path groups: builtin → external → `@/*` alias → relative.

2. **Prettier config** — going with the issue body's proposed defaults verbatim (single quotes, no semi, 2-space, 100-col). No deviation unless the scaffold's existing files surface real friction during the auto-format pass; if so I'll note in PR body.

3. **Out-of-scope flagged as follow-up suggestion (not bundled):** Custom AST-level ESLint rules from `CLAUDE.md §1` (`db.select()` ban, `requireSession()` enforcement) — these need a discrete ticket with a design pass on rule-author choice (`@typescript-eslint/utils` custom rule vs `eslint-plugin-no-restricted-imports` shortcut). I'll mention this in the PR body and you can decide whether to file it now or wait.

4. **One risk to call out: `eslint-plugin-tailwindcss` + Tailwind 4 compatibility.** The plugin historically reads `tailwind.config.js`; Tailwind 4 moved to CSS `@theme` and no longer requires a JS config. If the plugin doesn't auto-detect Tailwind 4 cleanly, I'll either (a) pin to a plugin version that supports v4 or (b) skip class-name validation and keep only class-order (which the Prettier plugin already handles canonically). Will document in PR body either way.
