# M2 — Core redesign

Goal: make Phase 2 information actually readable at /v2/[lang]/latest. After M2, the new app is rendering today's report end-to-end — just gated behind basic-auth.

## Components

### 1. Hero section

Top of `/v2/[lang]/[date]` and `/v2/[lang]` (latest). Reads from `web/public/reports/<lang>/<date>.json` (the JSON sidecar shipped today; do NOT re-render markdown).

Structure:
- Tier banner with `--tier-current` (CSS custom property set via `data-tier={tier.index}` on the parent — pick up from there in CSS).
- VIX value: mono font, large (text-6xl or so), weight 700.
- Right-aligned secondary stats: cash target %, buy size %, range.
- Tier action label: 觀察 / 警戒 / 等 in the language of the page.
- Single-sentence "today's read" pulled from `synthesis.market.read`. Truncate to first 2 sentences if longer. Skip rendering if synthesis is missing (graceful degrade — the JSON sidecar's synthesis field can be absent, per Phase 2 Commit 7's normalization).

### 2. Watch List with severity classification

Compute severity client-side from each holding's `flags` array:

```
CRITICAL: 'event_play' in flags AND 'earnings_within_3d' in flags
          → red border + top of list + larger visual weight
HIGH:     'deep_drawdown' in flags
          OR ('underwater' in flags AND vs_avg_cost < -0.20)
          OR 'earnings_within_7d' in flags
          → orange border + bigger than MEDIUM
MEDIUM:   'below_200dma' in flags AND 'below_50dma' in flags
          → amber border
LOW:      'buy_list_member' in flags AND no other watchworthy flags
          → gray, deprioritized (smaller, lower in list)
```

Sort by severity (CRITICAL first), then by ticker alphabetical within each severity bucket.

Visual weight literal: CRITICAL items are physically bigger than LOW items (e.g., CRITICAL = `text-lg p-6`, HIGH = `text-base p-5`, MEDIUM = `text-base p-4`, LOW = `text-sm p-3`).

### 3. Holdings — desktop table, mobile cards

Desktop (≥768px): redesigned table. Columns same as today (Ticker, Last, vs avg cost, RSI, vs 50DMA, vs 200DMA, vs 52w high). Mono numerics. Subtle row hover. 1px borders, no shadow.

Mobile (<768px): collapse each row to a vertical card. Each card shows:
- Ticker prominent (text-xl, bold)
- Last + vs_avg_cost on the same line, also prominent
- RSI / MA% / 52w high as a secondary line, smaller, mono
- NO horizontal scroll. Test at 375px width.

### 4. Snapshot grid

Currently 9 rows in a vertical table → 3-column grid of compact cards on desktop, 2-column on tablet, 1-column on mobile.

VIX gets its own emphasis: 1px border in `--tier-current`, larger card. Other indices secondary.

### 5. Footer

```
Generated 14:23 Asia/Taipei · 03:23 your local time · not investment advice
GitHub: https://github.com/crotchblow-prog/stockpulse
```

User-local time computed client-side via `Intl.DateTimeFormat`. Asia/Taipei is in the JSON sidecar.

# M3 — VIX sparkline + i18n + OG card

Goal: data viz + language switcher + shareability. After M3, the new app feels like a real product even though it's still gated behind /v2/.

## 1. VIX sparkline

`recharts` LineChart, **30 data points** read client-side from prior dated JSON files at `/reports/<lang>/<YYYY-MM-DD>.json`. Implementation:

- Server component: `web/lib/vix-history.ts` reads the last 30 dated JSON files via `fs.readdir`, extracts `vix_value` from each, returns `Array<{ date: string, vix: number }>`.
- Client component: `<VixSparkline data={data} currentTier={tier.index} />`. Renders LineChart with:
  - Tier color bands as `<ReferenceArea>` shapes at 5% opacity:
    - 0-15: `--tier-0`, 15-18: `--tier-1`, 18-24.6: `--tier-2`, 24.6-29.5: `--tier-3`, 29.5-35: `--tier-4`, 35+: `--tier-5`.
  - Single line, neutral color (text-muted).
  - Right-end dot in `--tier-current` color.
  - Mini-axis: only label today's value + 30d high/low.
- Position: hero right side on desktop (split layout 60/40), below tier banner on mobile (full width, fixed aspect ratio).

Bundle size watch: if recharts gzipped is >100KB, lazy-load it via `dynamic(() => import(...), { ssr: false })` so it doesn't block initial paint.

## 2. i18n language toggle

`web/lib/i18n.ts` — minimal custom solution. One dictionary per locale, key-based lookup:

```ts
type Locale = "en" | "zh";
type Dict = { [key: string]: string };
const dicts: Record<Locale, Dict> = {
  en: { "watch_list": "Watch List", "holdings": "Holdings", ... },
  zh: { "watch_list": "關注名單", "holdings": "持倉", ... },
};
export function t(locale: Locale, key: string): string { return dicts[locale][key] ?? key; }
```

Toggle in top-right nav: `EN | 中`. Implementation:
- URL is the source of truth: `/v2/en/...` vs `/v2/zh/...`.
- localStorage persists last choice across visits — if user lands on `/v2/` (no lang), redirect to last choice or `/v2/en` default.
- Toggle is just two `<Link>` components. Full reload is fine — Next.js handles it cleanly.
- SEO `<link rel="alternate" hreflang="en" href="/v2/en/..." />` + same for zh on each page.

## 3. OG card per date

`web/app/v2/[lang]/[date]/opengraph-image.tsx` (Next.js convention).

- 1200×630, dark theme matching the app surface (`--bg-base`).
- Layout: VIXPulse logotype top-left, date below. Center: huge VIX value (mono, weight 700), tier badge with `--tier-N` color. Bottom: holdings count + Asia/Taipei timestamp.
- Cache: Next.js handles this via the file convention — generated once per date, served static after first request.
- No image asset yet (Carina will provide a logo later). Pure typography for now.

Same convention for `/v2/[lang]/page.tsx` (latest) — wires to the most recent dated OG card.
