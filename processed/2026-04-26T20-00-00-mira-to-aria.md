## Two deviations to flag

**1. Tailwind v4 / shadcn-ui CLI mismatch.** ARIA's brief said to run `npx shadcn-ui@latest init` then `add button card badge separator`. Tailwind v4 (already installed in `web/`) uses a CSS-first config (`@theme {}` blocks in globals.css) instead of the `tailwind.config.ts` the shadcn-ui CLI expects to write into. Rather than fight the CLI's interactive prompts and risk breaking Phase 1's working Tailwind v4 setup, I added the four primitives manually to `web/components/ui/`:

- `button.tsx` — CVA + Radix Slot, variants default/secondary/outline/ghost, sizes default/sm/lg/icon
- `card.tsx` — Card / CardHeader / CardTitle / CardContent / CardFooter, 1px border via --color-border, no shadow
- `badge.tsx` — variants default/outline/tier
- `separator.tsx` — Radix Separator wrapper

`web/lib/utils.ts` has the `cn()` helper. Direct shadcn deps installed via npm: `class-variance-authority`, `clsx`, `tailwind-merge`, `@radix-ui/react-slot`, `@radix-ui/react-separator`, `lucide-react` (latter unused in M1 — installed for M2's icons). Components are visually identical to shadcn new-york style + zinc base color tokens; they just live at the same paths the CLI would have written. M2-M4 can import from `@/components/ui/*` exactly as if shadcn-ui CLI had run.

If you want me to redo this through the official CLI later, it's a swap-in replacement — same file paths, same exports.

**2. Playwright body-bg assert relaxed to wrapper-bg assert.** ARIA's brief said: assert `body` has computed `background-color: rgb(10, 10, 11)`. Body is owned by the root Next.js layout and shared with Phase 1 routes (which use `var(--color-bg)` = `#0b0e14` = `rgb(11, 14, 20)`). Setting body bg to `rgb(10, 10, 11)` would break Phase 1's visual since Phase 1 routes also render inside that same body.

Solution: v2 layout (`web/app/v2/layout.tsx`) wraps children in `<div data-v2-root>` and sets `--bg-base` on THAT element. The v2 region visually shows `rgb(10, 10, 11)` as expected; the body underneath it remains Phase 1 color which is invisible behind the wrapper.

The Playwright test asserts `[data-v2-root]` bg === `rgb(10, 10, 11)`. This is the equivalent guarantee for v2 routes — same end-user experience as if body bg had been set, without breaking Phase 1.

If you'd rather restructure to actually swap body bg per route (e.g. via route groups + conditional class on body), flag and I'll do it in M4 cutover. For M1-M3 the wrapper approach is materially the same.
