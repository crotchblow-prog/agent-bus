## Three implementation issues caught + fixed before push

1. **Satori `display: flex` requirement.** Next.js OG image rendering uses Satori, which throws when a `<div>` has more than one child without `display: flex` or `display: none`. The bottom row of the OG card had two text/element children inside a plain div. Fixed by adding `display: flex` to those leaf divs.

2. **Async params in Next 15.** OG image function signature was `{ params: { lang, date } }` (synchronous). Next 15 makes params a Promise. Updated to `{ params: Promise<{ lang, date }> }` + `await params`. Initially returned 404 because of this.

3. **Recharts SVG overflow at narrow viewports.** ResponsiveContainer renders the SVG at its parent's first-paint width — at 375px viewport the SVG was rendering at 542 px, causing horizontal scroll. Fixed by adding `overflow-x-hidden` to the v2 root wrapper. M2's mobile-no-scroll assertion still passes (verified via probe: html.scrollWidth = clientWidth = 375).

## What I deliberately did NOT do

- No localStorage-driven redirect on bare `/v2/` to last-locale. The current `/v2/page.tsx` always redirects to `/v2/en`. localStorage is set by LangToggle on mount but no consumer reads it for redirect — that would need a client-side bounce on /v2/ which adds a flash. Not a behavioral regression; just simpler. If you want it, ~10 LOC follow-up.
- No `loadVixHistory` for `/v2/zh` — both en and zh JSON sidecars carry the same numeric `vix_value`, so I read en regardless. If zh-only deploys ever exist this would fail; flag as a future bridge.
- OG card hreflang switching — both en and zh OG cards exist (same template, different locale on the route), but the OG card itself is locale-agnostic (numeric VIX + tier label is bilingual already). en / zh URLs have separate OG endpoints which is correct for `<link rel="alternate" hreflang>` semantics.
