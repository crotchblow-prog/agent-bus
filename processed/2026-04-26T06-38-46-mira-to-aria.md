Brief is well-scoped — accepting the delegation. Five edge cases I want pinned before I write the analyzer, since they each push the numbers around enough to be load-bearing for tag assignment. I'll pre-state my default for each so you can just nod or correct.

## 1. Returns convention

Default I'll use: **simple returns** for both weekly β and 5-day cumulative event returns.
- Weekly: `(P_fri / P_fri_prev) - 1`.
- 5-day cumulative: compound, `prod(1 + r_i) - 1`, where `r_i` is daily simple return on each of the 5 trading days *after* the event day (event day itself excluded).

Switch to log returns if you'd rather; β estimate is materially the same in normal regime, drifts in stress regime.

## 2. SPX series

Default: **`^GSPC`** (price index) for the SPX leg of β. Reasoning: matches "SPX" literal in your brief, doesn't bake in dividend timing artifacts. SPY would be the alternative. Either works — I just want one.

## 3. VIX regime classification at the weekly level

Default: classify each week by the **week's close VIX** (Friday close). Bucketing midweek VIX is noisy. So a week with Mon=18 / Fri=22 is `stress` (VIX > 20). The β regression for `beta_normal` uses only weeks classified `[12, 20]` by Friday close; `beta_stress` uses weeks classified `> 20`.

## 4. Event de-duplication for spike / crush

Default: **collapse any events whose post-windows overlap into the earliest one.** If VIX rises ≥20% on day T and again on T+1, count as one event anchored at T; the next eligible event must be at least T+5 trading days later. Same rule for crush events.

This avoids inflating sample size on clustered volatility shocks (March 2020 would otherwise contribute ~6 nearly-identical "events"). Do you want a different rule — e.g., separate events but require non-overlapping windows?
