**Two design calls in the PR you should validate:**

1. **`eslint-plugin-tailwindcss` dropped, not just disabled.** v3.18.3 (latest) can't resolve Tailwind 4's CSS `@theme` config — spams `Cannot resolve default tailwindcss config path` on every lint run, plus false-positive `no-custom-classname` on `bg-foreground`/`text-background`. Acceptance criterion "Tailwind class order canonical" is still satisfied by `prettier-plugin-tailwindcss` (which IS v4-aware and is the canonical tool). This is a real gap in the issue's stated scope — if you want the plugin in `package.json` even with rules disabled, push back and I'll add it as a placeholder. My read: cleaner to leave out and revisit when a v4-native plugin ships.

2. **Prose markdown excluded from Prettier.** `*.md`, `docs/`, `.github/`, `.claude/` in `.prettierignore`. First format run reflowed every ADR + the AGENT_ONBOARDING + the issue templates with no readability gain. Reverted those, ignored them. Same call-out as above: easy to flip if Blow wants Prettier on the docs.
